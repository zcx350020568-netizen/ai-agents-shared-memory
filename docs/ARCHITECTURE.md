# 架构说明

## 四层记忆

1. **入口与路由**：`AGENTS.md` 提供工具入口；`00-索引/AI入口.md` 规定开始/结束步骤；`AI数据层.md` 将任务关键词映射到具体页面。
2. **长期知识**：`30-方法/`、`50-技能/` 和项目页保存核实过、能跨会话复用的材料。
3. **会话连续性**：`40-协作/当前进度.md` 保持短小；不同任务通过新建交接页避免互相覆盖。
4. **本地私人层**：画像、账号、密钥和私密记录留在 Git 忽略路径，不进入共享版本历史。

## 知识流转

```text
外部来源或会话发现
        ↓
20-事件/日志索引.md 或 90-其他/收件箱.md（记录来源，标记待审）
        ↓ 人工/所有者审阅、事实核对、敏感信息检查、去重
30-方法/、项目页、技能页或决策记录
        ↓ Git diff 审阅、提交、推送
其他设备与可读取仓库的 AI
```

Inbox 是待审区，不等于事实库。未经核实的条目应标记推断或待确认；拒绝的内容可记录原因后归档，不必强行纳入长期记忆。

## 同步与冲突

Git 是版本和多设备同步层。Obsidian 负责编辑和导航，AI 通过文件权限读取内容。GitHub 仓库不共享模型内部上下文，也不自动授予 AI、设备或协作者权限。

同一个进度页只允许一个活跃写者。其他并行任务新建交接文件。冲突由人或 AI 保留双方信息后人工整理；不强制推送、不自动删除文件。

## 自我维护

每次需要时按清单检查索引、来源、过期信息和错误模式。周期性扫描是可选的人工工作流，不会创建 cron、后台任务或自动修复。修复建议先展示 diff；删除、批量迁移和外发必须经过仓库所有者确认。

## 工具适配

根目录和隐藏目录中的工具说明只是入口适配层；真正规则保持在共享 Markdown 页面中，避免每个 AI 工具维护不同版本。具体工具若不支持自动读取，用户可手动提供通用提示和相关页面。
